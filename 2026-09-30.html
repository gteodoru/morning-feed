Error analysis is the eval work that actually matters

Decoding AI Magazine · X — @HamelHusain · Sep 29

Replay your agent's real failures after every prompt, tool, or model change — pass/fail labels, failure cohorts, one cheap evaluator per cluster.

The piece every agent builder should internalize: you can't write unit tests for prompts, and integration tests don't scale across the combinatorial explosion of an agent's behavior. What works is the error analysis framework (popularized by Hamel Husain and Andrew Ng): record real runs, hand-label a sample as pass or fail with a short critique (never a 1–5 score — a "fail" is actionable, a "3" is not), fix the obvious, cluster the rest by failure type, rank by frequency × severity, then write one cheap evaluator per cluster and re-run it after every change.

The article demonstrates it with Kitaru, an open-source-style tool by ZenML Labs for capturing agent sessions and replaying them with the same context: its replay mechanism caches tool outputs so a replayed session sees identical context, and only changed tools or new arguments run from scratch. The motivator quote: in LangChain's Terminal-Bench experiment, changing only the harness — same model — moved a coding agent from ~30th place into the top 5. The harness is what makes the agent good, not the model.

And right on cue, Hamel himself is stress-testing Anthropic's new automated eval tooling (/claude-api build-eval + hillclimb): his verdict after hands-on use is that it creates evals before looking at data and uses a markdown "tell me which labels are off" instead of a real annotation app. Data-first, custom annotation UI — the framework from the Decoding AI piece is exactly the discipline he wants the automation to serve.
