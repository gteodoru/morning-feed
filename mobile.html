Anthropic's Messages API, rewritten in Rust by Claude

Latent Space, via X · Oct 30

Claude rewrote Anthropic's core API from Python to Rust — and nobody noticed, because shadow traffic proved parity first.

The Messages API — the endpoint every Claude app and agent calls — was a Python monolith, and Anthropic was heading for what its engineers called a CPU wall: CPU is a fixed budget negotiated with cloud providers and split across products, agent sandboxes, CI and research, and agentic coding makes CI explode. So they did not strangler-migrate it over years. Claude wrote a full fork of the entire API in Rust while humans designed the system, then the team ran shadow traffic through the Rust fork, checking that Python and Rust returned identical outputs before moving real traffic. It was a pure port — no new features during the migration, with static analysis flagging any new Python feature that did not account for the Rust side.

The ballpark result, from Anthropic engineers on Latent Space: 40–50% less CPU and 10–20% faster time to first token, fully rolled out as of last week. Next is re-architecture, including storing conversation state server-side so callers stop resending the whole conversation. The lesson the engineers named is the one to steal: the plan to do the thing, and the verification of the thing, mattered most. And the replies noticed the real flex — tests good enough that nobody noticed the rewrite — plus the warning to copy the parity check on requests that should be refused, not just the ones that work.

A little determinism: how Sentry makes its agent behave, every time

David Cramer, via X — @zeeg · Oct 29

Don't cage the agent's reasoning — police its network boundary instead.

Sentry's agent, Junior, ships PRs, and some things must happen 100% of the time: a PR footer linking the trace, a co-authored-by line. Cramer's answer is not a better prompt — he argues skills and AGENTS.md almost never deliver determinism — but control at the network boundary. Every request out of the sandbox goes through a man-in-the-middle egress proxy: credentials never enter the sandbox (the proxy injects bearer tokens per request, and halts the turn with an authorization link if the user has not approved); a GitHub GraphQL mutation the agent should not make gets a 403 whose body tells it exactly which tool to use instead, so the agent complies and the tool adds the footer; requests carry signed, short-lived context so Junior cannot approve a PR even though its GitHub token can; and events (CI failures, review comments, merges) arrive as injected messages instead of polling loops.

The takeaway for anyone running agents in production: put determinism at the boundary — network policy, tool routing, event subscriptions — and leave the reasoning free. Cramer expects the next layer (should this run visual QA?) to need classifier models, not more prompt.

OpenRouter rebuilt its router on the cost of a good answer

OpenRouter, via X — @steipete · Oct 28

Price-only routing lets bad-but-cheap providers win. OpenRouter now scores what a good answer actually costs.

About 77% of OpenRouter requests go to models served by several providers, and the old router picked mostly by input-token price — which let bad-but-cheap providers win and invited pricing games like low input prices with overpriced cached or output tokens. The rebuilt router computes a per-request Routing Cost: what one try costs (effective price from measured traffic, including real cache-hit rates and input/output mix, plus the cost of waiting, with time-to-first-token counted on its own because agents wait for a first token on every tool call, plus a rate-limit penalty) multiplied by how often tries fail (errors and quality failures, mainly malformed tool calls). Providers near the best split traffic, with a floor for every provider and back-off for failing ones; conversations stay pinned to keep prompt caches warm.

Measured with a switchback experiment — alternating old and new routing in 3-hour blocks, because routing changes contaminate a normal A/B test — over 24 million requests: time-to-first-token down 16.9%, throughput up 16.3%, 429 errors down 46%, retries down 34%, at 6% higher cost per request. If you route models yourself, the idea ports directly: score providers on the cost of a good answer, not the sticker price.

Qwenputer: a computer compiled into Qwen's weights

Divyansh Agrawal, via X — @divagr1925 · Oct 28

A RISC-V CPU compiled into a language model's weights — no training, a compiler setting every weight.

Take stock Qwen3.5-4B, add 11 transformer layers in front of its 32, and write a 32-bit RISC-V CPU (RV32IM plus a bignum unit) directly into those layers — not by training, but by a compiler that sets every weight. The trick exploits Qwen3.5's Gated DeltaNet layers: each head keeps a state matrix, and with the forget gate set to 1, write strength to 1 and one-hot keys, each row becomes an exact, addressable memory cell — RAM that, unlike the KV cache, does not grow with context. The CPU is a circuit compiled into attention heads (lookups), feed-forward units (arithmetic) and DeltaNet heads (RAM); each instruction becomes a few generated tokens, so the decoding trace is the CPU's execution log.

The author's numbers: it passes the official riscv-tests, matches QEMU, ran 18 million instructions free-running without error, and normal text barely changes. DeepMind arithmetic jumps from 55% to 97.5% on big multiplication and 48.6% to 100% on long-integer tasks. Limits are real — an 18.8 GB checkpoint, a driver to hide trace tokens, a few tokens per instruction — but the conceptual payoff is the point: weights can hold a compiled machine, which is both a new kind of tool use (nothing leaves the model) and a new safety surface (reasoning hidden in RNN state, monitors a model cannot switch off).

How Anthropic ships the #1 LLM in the world, safely

Latent Space · Oct 27

Latent Space's episode with Anthropic's engineers on the Rust rewrite — the migration method, not just the result.

A Little Determinism

David Cramer · Oct 29

Sentry's David Cramer on putting agent determinism at the network boundary.

Why it matters: every agent fleet eventually faces the same failure — a step that must happen 100% of the time and does not. Cramer's essay reframes the fix from prompt engineering to systems engineering: credentials injected by a proxy, tool-routing denials returned as errors the agent can act on, signed short-lived context narrower than the token, events instead of polling. Takeaway: audit your own agent's boundary. The deterministic guarantees you need probably live in the egress proxy and the tool router, not in the system prompt.

How we rebuilt provider routing for better, faster inference

OpenRouter · Oct 28

OpenRouter's routing rebuild — the cost model and the switchback test behind it.

Why it matters: if you buy inference from multiple providers — or build a router for your own platform — this is the cost model to copy, and the experiment design to copy with it. Routing Cost (effective price plus waiting plus failure rate) replaces sticker price, and the switchback experiment solves the contamination problem that makes ordinary A/B tests lie about routing changes. Takeaway: measure your providers on the cost of a good answer, and be suspicious of any routing claim not backed by a contamination-aware experiment.

Proving and Improving the Platonic Representation Hypothesis with JEPAs

Balestriero & LeCun (arXiv) · Oct 30

Balestriero and LeCun's JEPA paper — why good views beat scale for cross-modal alignment.

Why it matters: Balestriero and LeCun turn a 2024 observation into a theorem, for JEPAs: if every modality's encoder trains on positive pairs that are two views of one scene, separately trained encoders learn the same representation up to one rotation. Next-token prediction is a JEPA with bad views — pairs from one document, not two views of one scene — which is why LLMs align with vision only through scale. A 109M-parameter text JEPA out-aligns 72B LLMs, and good views need 42x fewer samples than next-token prediction for the same alignment. Caveats: idealized assumptions, and the captions used were partly generated by a CLIP-based model. Takeaway: when you design training data, the choice of what counts as a positive pair may matter more than scale — a design lever for anyone building multimodal systems on a budget.

Was I wrong about open models & cyber risks?

Interconnects (Nathan Lambert) · Oct 30

Nathan Lambert revisits his open-models-and-cyber-risk thesis after Black October.

Why it matters: after a month Lambert calls Black October — PHP2Shell, GitLab, the Binance theft — he revisits his claim that an open-weight Claude Mythos would have been fine, and mostly stands by it, softened: expect a costly, forced industry update, an acceleration rather than a step change. His arguments are worth wrestling with: GLM-5.3 crossed a threshold a month ago with little public evidence of change; threat actors are businesses with set processes; closed models played the bigger part in recent hacks; and exploit damage was rising exponentially before ChatGPT, so a step change would show if AI were the bottleneck. The counter-camp matters too: almost all research measures offense, and closed-model refusals hit defenders. Takeaway: frame your own org's open-model policy around defense capacity, not just capability thresholds — and read the camps, not just the thesis.

Consensus: GOP Senate, narrow Democratic House. Disagreement: whether that is normal, a wave, or chaos — and whether to trust polls at all.
