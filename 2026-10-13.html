Anthropic measures the AI worm: small models are months from self-replicating on IoT

X — @badlogicgames (Mario Zechner) · Oct 12

A 26B model ran inference sharded across 15 off-brand Android TV boxes — and the trend line puts a ≤30B model at full-replication capability by year's end.

Anthropic split replication into four stages — find targets, gain execution, establish inference, keep propagating — and measured the least-studied one: getting inference running on strange hardware. Qwen3.5-9B got inference up on 8 of 9 hardware types; GLM-5.2 replicated end-to-end across a firewalled 8-node VPC in 4 of 5 trials; Gemma4-26B sharded across 15 ~$55 Android TV boxes at 0.39 tok/s. Pipeline parallelism was chosen for fault tolerance — a dead node can be replaced and its KV recomputed.

Two details worth stealing for your own agent work. First, the Memento harness — built on the open-source Pi coding agent — periodically restarts a fresh agent with the previous workspace plus a short notes file, which breaks the "fixation on a wrong idea" loop (one Qwen agent debugged package versions for hours when the bug was an incompatible endpoint). Second, their defense framing: drive R₀ below 1. Multi-GB payloads and sustained device-to-device traffic are ISP-visible signatures, and Mirai-style ISP quarantine cleared 92% of infections in 14 days. Zechner's response on X was half joke, half policy memo: don't build LLM worms on the Pi agent, and "dario, if you read this, call me — we need to pace the frontier."

For Gabriel: if you ship edge boxes or devices at the SaaS, this is your checklist — kill default creds, close open debug ports (ADB!), and watch for multi-GB inbound payloads. If you run long-horizon agents, the fresh-instance-plus-notes trick is a cheap anti-fixation pattern worth trying.

Quail's trie trick: classify 1.8× faster by decoding only at branch points

X — @sh_reya (Shreya Shankar) · Oct 12

Don't generate-and-parse. Build a trie of your labels, run the model only at branch points, and stop as soon as one label remains.

BigQuery AI.CLASSIFY and Snowflake AI_CLASSIFY-style systems prompt an LLM, let it generate freely, then parse a label — wasteful in tokens and fragile when the model invents a label. Quail runs the model inside its own engine, so it can constrain decoding to the label set. Their default operator, trie_decode, builds a trie of label tokens and only runs the model at branching nodes — 1.5 requests per doc in their 10-label support-ticket example.

On their 12-query benchmark (Qwen3-4B-fp8, one H100), Quail beat vLLM on all 12 — 1.8× geometric mean per query. The biggest wins come when multiple classifiers read the same traces: on one three-classifier trace analysis, 64% of vLLM's computed tokens were recomputation because LRU evicted the KV cache; Quail keeps document KV warm across operators. And a design note that generalizes: labels that diverge at the first token are nearly free — label design is a performance lever.

For Gabriel: this is exactly the plumbing the support-triage agent capstone needs. If you classify at scale with a hosted model, constrain to a trie, stop at the first unambiguous token, batch the stragglers, and keep the document KV warm for downstream operators.

Anthropic's "flows": Claude writes its own orchestration program

X — @latentspacepod · Oct 12

Past fixed coordinator-plus-subagent rosters: the lead agent writes a plan, then an orchestration program that launches agents, collects results, and manages phases.

From the packed Anthropic workshop at AI Engineer NYC (CJ Avilla and Harrison Stall, origin story: Claude Code's "a harness for every task"). The pain they're targeting is the human becoming the PR-approval bottleneck — their analogy is Unix → Linux, one person → layers of trusted maintainers. In the demo, a stock-watchlist scanner fans out one ticker per agent with isolated contexts, then a review phase checks findings and writes the report.

The Q&A details are the real substance: set a session budget, not an agent budget — the model doesn't know its budget, and telling it can make it "a little bit anxious." Flows cost "much more" than a single agent but were "much more effective at finding all of the details." Subagents can't message each other via the API; they share a filesystem, and every lead→subagent payload is inspectable in a Console graph. Research preview: "dreaming" reads a memory store plus past transcripts and writes back a reorganized one (dedupes, replaces stale entries).

The theme is converging across the lists: Aaron Levie amplified Pedro Domingos's point that in the limit, AI will be better at choosing its own harness once it sees the task, and Kempe's h1 paper showed hand-designed decompose-plan-assign harnesses losing to a frontier model with good Lean feedback. Treat flows as "throw test-time compute at hard problems": hard session budget, instrument the graph, filesystem as the inter-agent bus.

OpenCode 2.0: code mode by default, background subagents

X — @opencode · Oct 12

One background service, MCP servers composed as code instead of tool calls, and background subagents — tool composition is moving into code.

Three changes matter. First, the server now runs as one automatic background process; the TUI, web UI, and desktop app all talk to it, and scripts via @opencode/client auto-discover it — useful for scheduled agent tasks. Second, Code Mode: a minimal JS interpreter turns MCP servers and OpenAPI endpoints into functions the agent calls from a script — call, map, call again in one round trip. All MCP servers are in code mode by default, so you can "add a thousand of them with minimal context bloat." Third, background subagents (even with a different model — "spawn a background fable subagent to review this code") plus async shell commands and a hotkey to background a long foreground task.

The notable bet is code-mode-by-default: composing tools in code instead of burning N tool calls in context. Watch for it in Claude Code and Cursor; if the pattern holds, your harness design should assume tools get wrapped in generated scripts, not called one at a time. Breaking change: 1.0 plugins and the server API don't carry over.

Slop is a skill issue: give your agents a way to verify their work

X — @poteto (lauren) · Oct 12

Two things: give your agent a way to verify its own work, and make your codebase the memory that encodes your conventions.

poteto's post (3.7K likes, quoting dax) argues the slop conversation is one-sided — you can also observe, debug, and refactor far more code than before; even manually written code is "100x easier to maintain" now. The replies split into two camps. The agency camp (t1llmann, DanielLockyer): slop comes from being sloppy — models need guidance, limits, and verification hooks; iliaa adds that plenty of human code was slop too. The it-happens-to-you camp (Nan Yu): slop PRs landing on maintainers, colleagues merging slop — inbound slop you don't own isn't in your control. poteto's rebuttal: she means code specifically, and maintainers can shape the codebase so even non-technical colleagues' contributions converge.

The actionable half is concrete and it maps to a real product move this week: Amp's new GitHub listeners auto-subscribe any PR opened from an Amp thread to its comments, reviews, and CI — failures land back in the thread with context. Verification hooks plus a codebase that encodes conventions (tests, lint, types, docs your agents actually read). Nan Yu's point stands for inbound slop you don't own — that needs process, not just tooling.

Meta is back at the frontier: Muse Wonder and Wonder Full

Bloomberg — Tech In Depth / WSJ — Tech lead & What's News · Oct 12

A fourth US frontier lab — this time closed. The top model is gated behind a coding subscription, not the API.

Six weeks after Muse Spark 1.3, Meta Superintelligence Labs shipped Muse Wonder and Muse Wonder Full — trained on the Prometheus data center, ~1M-token context, text/image/audio/video in. The independent scores (Artificial Analysis Intelligence Index): Wonder Full 56, tying Claude Sonnet 5.5; GPT-6 Astra, Gemini 4 Argon and Claude Fable 5.1 at 53; Opus 5.5 at 58; Wonder at 52. Meta's own scorecard: SWE-Marathon 57.5 vs Opus 5.5's 46.3, but losses on Terminal-Bench 4.0 and HealthBench Pro. Early third-party reads: Mollick says "a good model," big progress since April; Claire Vo's bench says agentic tasks crushed, front-end design "woof."

The commercial structure is the story. Wonder is on the API at $4/$20 per million tokens (same as Opus 5.5, cheaper than Astra's $10/$50). Wonder Full — the model that ties Sonnet 5.5 — has no API at all: it's only in Muse Code subscriptions ($50/$200/mo), which default to Contributor data mode (your prompts, code, and outputs can train future models; opt-out only applies going forward). And the open-weights era is over: Meta says Spark's open weights are "coming soon," but Wonder is "too big" with "potential safety concerns."

The reaction was as loud as the launch. Curran (200K+ views): "pacing is out the window" — one US-lab defection breaks any slowdown pact, and Zuckerberg told the FT he rejects slowdown calls outright. Charlie Marsh's counter: "publishing intelligence without cost is not-great" — independent scores without reproducible cost numbers don't help buyers.

The WSJ's Tech lead (Meghan Bobrowsky) frames the launch as a test of Muse, Meta's personal-assistant agent launched last month: Wonder will soon power it for subscribers on the $20 and $100/month tiers. The agent has nearly 9M global downloads, but growth is slowing and 14-day retention lags ChatGPT (Sensor Tower). The practical obstacle: websites keep blocking agents — Jefferies's Brent Thill found his Muse blocked by Home Depot and Spectrum, and Amazon blocked Muse purchases at the end of September. Meta stock rose 3% Monday; rivals are circling — OpenAI's Dots agent, Google's Gemini Spark, and startup Instinct, which the WSJ calls Muse's main competitor.

For your buying decisions: Opus-level price, strong long-horizon coding claims, weaker terminal/health — and read the data-mode defaults before staff use Muse Code.
