The harness is now part of the model

X — @ClementDelangue · Oct 5

Hugging Face turned unmodified coding agents into RL environments — and proved the harness, not the weights, decides the leaderboard.

The same model weights scored 62% under Mini-SWE-Agent but only 33% under Claude Code. Hugging Face's insight: RL training usually happens in a reimplemented scaffold, so "most models get trained in a scaffold nobody actually ships." Their fix is elegant — don't rewrite the harness, put a proxy in front of the model. The proxy speaks the four formats coding agents use (OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Gemini), forwards to vLLM, records the exact token IDs and logprobs, and hands TRL sequences it can train on. Ten harnesses run through it unmodified.

On Liquid AI's LFM2.5-2.6B: training in one harness mostly helped that harness (OpenCode 34% → 58%); training across four at once lifted all four (avg 42% → 54%); SFT on 3,189 rollouts from Qwen3.8-27B plateaued at 47.5%, below both RL runs. Tool calls fell 31% on solved tasks. Honest caveat in the model card: best-checkpoint selection used the test set.

The replies are the point: @Teknium calls the real-harness-in-the-loop "so valuable," @CarlWalkerPM says the 62-vs-33 gap "quietly invalidates a lot of model-vs-model comparisons," and the skeptic (@johnroodepic) asks the right question — how does a four-harness model do on a fifth it never saw?

Takeaway for your role: if the Riot foundation platform ever ships agents on open models, you can RL them inside your own harness with your own reward (fewer tool calls, read-only behavior) without forking your agent. Benchmarks need to list the harness as a first-class variable.

Pi Durable: crash-proof, multiplayer agents

X — @pidotdev · Oct 5

A compact, readable reference design for agents that survive crashes and can be steered by several people at once.

Everything the harness runs is a task that checkpoints before moving on: each model request, tool call, and compaction. After a crash, a new process opens the same storage (memory, JSONL, or SQLite — the code avoids Node APIs so it runs on Bun or a Cloudflare Durable Object) and resumes. Cut-off model requests are re-sent; tools rerun only if marked replay-"safe." A requestId makes submissions exactly-once. Conversations can fork (Slack channel to thread), each with its own model, tools, and working directory; hooks store decisions in "memos" so an approval isn't asked twice after a restart. Any number of clients can attach and steer the same conversation.

The builder takeaway the authors push: mark every tool's replay safety explicitly, key side effects with idempotency keys, and treat subagents as conversations you own so aborts and crashes clean up bottom-up. At ~15K lines it's a reference design your own agents could read. (Yesterday's tip covered the Cloudflare Agents SDK integration; this is the harness itself, which shipped with Pi 1.0 on Oct 1.)
