AI found a decade-old hole in the engine under 70% of the web: php2shell

X — @OpenAI, @eastdakota, @NSACyber; WSJ — Robert McMillan; LinkedIn Editors · Oct 21

Two critical flaws (CVSS 9.2) in the PHP engine itself let unauthenticated attackers run code or read server memory on versions back to PHP 5.4 — found with frontier AI, disclosed after a two-month coordinated fix. Cloudflare saw exploit attempts go from thousands to millions within hours.

Two CVEs (CVE-2026-109618 and CVE-2026-109619, both CVSS 9.2) in core PHP, not in any app on top of it. Wiz demonstrated unauthenticated remote code execution on stock WordPress, Drupal and Joomla containers, plus an app-agnostic leak of worker memory that can contain other users' passwords, tokens, API keys and certificates. Every PHP version of the past decade, back to 5.4, has at least one of the bugs.

The root cause pattern: when an out-of-memory error kills a request mid-startup, PHP frees the request's memory but forgets to clear global pointers to it; the next request in the same worker trusts the stale pointer, and the attacker has refilled that memory. Wiz describes four instances of this — an upload-progress unserializer use-after-free, remote memory disclosure via a dangling session-ID pointer, a fatal-error backtrace use-after-free, and an OPcache type confusion.

Who found it is disputed in public: OpenAI's post says Calif identified a flaw using GPT-5.6 Sol inside its Patch the Planet program, with Wiz also independently discovering both; Wiz says it found them Aug 19 with Wiz Atlas, Gemini 4 Argon and GPT-5.6 Sol, and Google's Raluca Ada Popa is quoted crediting Gemini. OpenAI's post drew a community note, and replies cite Fortune saying Calif told OpenAI about an Aug 1 finding first. OpenAI proposed a five-stage AI-era disclosure playbook and committed $1B in subsidized Daybreak access for 'Frontline Defenders.'

The reaction is the lesson. Cloudflare's Matthew Prince: thousands of exploit attempts in the 10 hours before the announcement, tens of thousands in the 45 minutes after, 'millions now.' The NSA: if you can't patch, take the system offline. Ethan Mollick: 'Acceleration of attack and defense, at inhuman speeds, interacting with the very human systems that need to react to them.' One camp put the asymmetry plainly: 'AI found the flaw in hours. Patching 70% of the web's servers will take humans months. Discovery scales; maintenance doesn't.'

What to do this week: patch to 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 (distros backport without changing the version string — check the package changelog), confirm your WAF has the stopgap rules, and look for the pattern in logs: crafted multipart POSTs with many empty file fields or a PHP_SESSION_UPLOAD_PROGRESS field, followed by memory-limit errors or 500s.

The Journal's own exclusive frames it as 'one of the most severe online vulnerabilities ever,' with experts now racing to patch systems before attackers use AI to discover and exploit the flaw themselves — the double-edged moment in one sentence: the same tools that found the bug are lowering the bar for exploiting it.

tsrs: an agent-written Rust port of the TypeScript compiler joins Oxc

X — @voidzerodev · Oct 21

Up to 8x faster than TS 7.0 with ~70% less memory — and the learning bit is how it was built: one engineer asked Claude Opus 5.5 for a faithful port and says he 'wrote zero code.'

It's a drop-in replacement for the TypeScript 7 compiler and language server written in Rust, aiming for 100% conformance with TS 7.1. Cloudflare and VoidZero now maintain it inside Oxc (the Rust JS toolchain) 'in close collaboration with the TypeScript team' — 'we are not forking TypeScript.' Up to 8x faster than TS 7.0 with ~70% less memory, and TS 7.1 beta is itself up to 2.5x faster than 7.0, partly from optimizations upstreamed from tsrs.

Why Rust when TypeScript already went to Go? WebAssembly. Go's garbage collector comes along when compiled to Wasm; Rust's memory model makes a small Wasm build practical, so a full type-checker can run in a browser or on Cloudflare Workers sandboxes.

The origin story is the learning bit: Owner's Max Schwenk asked Claude Opus 5.5 for a faithful port of the Go compiler and says he 'wrote zero code.' It was tested against TypeScript's 15,197 conformance cases; after adding a type printer, 99.97% of error baselines matched (all but 4 of 13,462). Owner's 37,000-file monolith went from 80 seconds and 19 GiB to typecheck on TS 7.0 to 7 seconds in CI and ~12 on a MacBook — which lets several coding agents run checks in parallel on one laptop. Try it: pnpm add -D tsrs, then pnpm exec tsrs --noEmit. Pull requests are closed for now.

3.5 months, under $10M all-in, from an empty repo — agents wrote over 99% of the code. The thesis: the bottleneck moves from headcount to compute, data, and the judgment of whoever directs the agents. (Caveat: self-reported, no evals yet.)

Mirendil-Base is a coding-specialized base model in the 100B–500B parameter range, built by one researcher in 3.5 months with under $10M of compute all-in (research, small-scale experiments, the final run, the agents' token spend, data processing). They started from an empty repo on top of PyTorch and JAX, used only public data — GitHub, web, public datasets — no purchased data, no distillation, no synthetic data. Larger versions (Base-Large at 500B–2T and Base-XL at 2T–10T) are training.

The thesis is the org-change one: the bottleneck moves from headcount to compute, data and the judgment of whoever directs the agents. The camps were impressed ('way more impressive than a bunch of benchmarks'), asked method questions (how the automated loop scored proposals, whether small-scale wins hold after post-training), and asked the labor question: 'how many hours that researcher spent reading agent output versus writing prompts… that's the part that doesn't parallelize.' One important caveat: it's all self-reported — no benchmarks or evaluations are out yet, promised 'sooner than you think.'

eMudhra's revoked keys were 4, 56, 66, 115…

X — @mitsuhiko, @AnzalAbidi · Oct 21

The eight revoked CA intermediates had single-byte private keys — an HSM test-script bug, wrong labels, signed into real certificates in April 2025. Browsers block them; curl, certifi, Go and Docker images still need updates.

The new detail since Tuesday: the eight revoked CA intermediates' private keys were the numbers 4, 56, 66, 115, 155, 156, 230 and 237 — single-byte values instead of random 384-bit numbers, recoverable by trying all 256 possibilities. Per Abidi's recap (not independently checked), a bug in eMudhra's HSM key-wrapping test script generated a second set of weak keys, operators picked the wrong key labels and signed them into real certificates in April 2025, and when revocation-list signatures started failing in May 2025 someone switched the signer to the weak keys 'and closed the ticket.' Ronacher says he now holds a certificate for hosts he doesn't control that 'actually works for so much software.'

What still needs doing: browsers already block these, but curl, Python's certifi, Go binaries and Docker base images don't check revocation lists — update ca-certificates, certifi and Go (Abidi lists 1.27.3 / 1.26.10). The thread's substantive hypotheses: a script that took one byte of a real key, a test-mode 8-bit key path run in production, and 'a pre-signing check that rejects implausibly small private scalars would have caught all eight.' (Abidi's recap also covers a 10.6 TB PingCAP/TiDB Cloud breach — cloud credentials committed in PingCAP's own repos, 22 days of exports with no alerts — which the digest author did not verify.)
