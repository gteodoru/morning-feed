Cloudflare's Pi harness: durable agents on the Agents SDK

Added Oct 4 · original article

Cloudflare is turning its Agents SDK into a neutral host for outside agent harnesses, starting with Earendil's crash-proof Pi.

What the post says

Cloudflare published a changelog entry (Oct 2, 2026 — date per URL slug; the post body carries no byline date) announcing that the Agents SDK now supports Earendil's Pi agent harness via a new PiHarness "Lifecycle capability." The pitch: long-running agents whose work is durably persisted inside Durable Objects, surviving restarts, crashes, and network issues — even mid-turn. Cloudflare explicitly calls it "our first step toward first-class support for third-party agent harnesses on Cloudflare."

This is not a new Cloudflare service; it's an SDK integration pattern. You install agents@latest plus two optional peer deps (@earendil-works/pi-durable and @earendil-works/pi-ai), configure Pi's Harness via a factory, register it with this.lifecycle.use(this.harness), and drive it with this.harness.prompt(). The reference example repo includes WebSockets, a browser UI, and a @cloudflare/computer Workspace for tool execution.

How it works (technical details)

The division of labor is the interesting part. Pi Durable owns the agent harness — transcript, loop, task recovery — while the SDK's Lifecycle keeps the agent alive in the Durable Object. Lifecycle is presented as a core SDK concept: "ensuring that long-running work can run in a Durable Object, surviving restarts, crashes, and network issues," with more Lifecycle capabilities promised soon.

Storage: Pi Durable's Harness.open() is handed the Durable Object's SQLite database (confirmed via Smith Wiki's docs investigation; Cloudflare's own design RFC shows pi tables namespaced under cf_agents_pi_*). Models come through the new agents/models/pi-ai entry point, bridging Cloudflare models (AI Gateway, Workers AI; the example uses @cf/moonshotai/kimi-k2.7-code) or your own pi-ai provider. Tools and system-prompt sections are delivered as "extensions" with explicit replay: "safe" declarations — Pi's mechanism for saying a tool call may be re-run after a crash (safe reads rerun; deployments/payments never do).

Why this was cheap to build: Earendil's Pi Durable (launched Oct 1, the day before, alongside Pi 1.0) checkpoints every task to storage before proceeding, and its SQLite backend uses no Node APIs — "with a small adapter it runs inside a Cloudflare Durable Object." That single design choice made the integration possible.

What to take away

Three takeaways. First, architecturally this is Cloudflare declaring the harness layer a commodity it will host rather than own: runtime (Agent on Durable Objects) is decoupled from harness (your loop / Think / beta PiHarness), channels, and tools — model providers and hosting runtime separate too. Second, it's experimental on both ends: Pi Durable is explicitly experimental and its API may change; PiHarness is labeled beta. Watch-and-prototype, not production-roadmap material this quarter. Third — and this is the meaningful signal — Cloudflare is positioning the Agents SDK as the neutral, durable-execution substrate for any third-party harness. For a tech lead building an AI foundation platform, that's the direction of travel: the moat moves from the agent loop to the persistence/wake primitives.

What people are saying

Up front: public discussion of the Cloudflare post itself is thin — no HN thread, no Reddit thread, no X posts, no newsletter coverage found. It's a quiet changelog entry two days old, landing one day after Earendil's Pi 1.0 / Pi Durable launch (Oct 1), which dominated the conversation — Pi 1.0 hit #1 on HN (1,200+ points; an aggregator later reported ~1,678 pts / 598 comments) with Pi Durable also in the top 10. The closest voices:

Smith Wiki (documentation investigator, updated Oct 3): "The adapter uses the Durable Object's SQLite database. Lifecycle jobs wake interrupted sessions. Pi Durable owns the transcript, agent loop and task recovery... PiHarness is beta. Pi Durable is experimental, and the API may change. This is a documentation finding; we have not tested a deployment."

Cloudflare's own engineers, via the public design RFC in the agents repo: "Pi owns operation acceptance, transcript state, provider attempts, tool intent and settlement, retry waits, and recovery," while Cloudflare's durable primitives deliver wakes, output streams, and the browser protocol. Notably, the RFC initially proposed PiHarness as example-local code — the changelog post shows it graduated to a first-class SDK export.

Ashraf Chowdury (dev.to), on the parent Pi Durable release: "Durability is the next gap. Most agent demos die on the first crash. Checkpointing plus replay policies is where production agents are headed."

HN discussion on Pi Durable (via groundtruth.day's summary): practitioner Luke Buehler argued durable harnesses help with "unattended work, recovery, monitoring, and shared steering"; others questioned "the abstraction and the absence of first-class sandboxing or policy controls"; Armin Ronacher explained the team tried more elaborate approaches and chose a simpler storage interface. Groundtruth's own caution: "Persisting the work graph does not restrict its tools. The application must define storage durability, who may steer a conversation, and how tool execution is contained."

Also on the radar of Chinese-language AI builders: a YouTube explainer linking the Cloudflare PiHarness docs.
