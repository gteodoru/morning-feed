Vercel's Eve: the 'Next.js for agents'

Added Oct 10 · original article

Vercel's eve turns agents into inspectable directories and bakes in the production plumbing — durability, sandboxes, approvals — that teams keep rebuilding. Its closest rival is Flue, and the choice between them is mostly a choice of cloud.

What it is

Eve is Vercel's open-source (Apache-2.0), TypeScript-first agent framework, launched June 17, 2026 at Vercel Ship — pitched as "Next.js for agents." The core idea: an agent is a directory. agent/agent.ts holds the model config (with AI Gateway provider fallbacks), agent/instructions.md is the system prompt, tools/ holds typed TypeScript functions (the filename becomes the tool name), skills/ holds Markdown playbooks loaded on demand, plus subagents/, channels/ (HTTP by default; Slack, Discord, Teams, Telegram, Twilio, GitHub, Linear), schedules/ (cron, deployed as Vercel Cron Jobs), and connections/ (MCP servers or OpenAPI APIs; eve brokers auth so the model never sees credentials). Authoring is filesystem conventions with no boilerplate runner: npx eve@latest init my-agent, eve dev for a terminal UI.

Batteries included: every conversation is a durable workflow with each step checkpointed — sessions pause, survive crashes and deploys, and resume where they stopped (built on Vercel's open-source Workflow SDK). Agent-generated code runs in an isolated sandbox (Vercel Sandbox microVMs when deployed; Docker, microsandbox, or just-bash locally — the backend is swappable). Human-in-the-loop via needsApproval on any tool (the agent pauses without consuming compute, renders as Slack buttons in Slack). Every run emits standard OpenTelemetry traces exportable to Braintrust, Arize, Honeycomb, Datadog, or Jaeger; scored eval suites (defineEval) run locally, against deployed apps, or in CI as a deploy gate. Deployment is vercel deploy — the agent is an ordinary Vercel project. Vercel says it uses eve internally for v0 and its 100+ production agents.

Repo state (github.com/vercel/eve): 5,513 stars, 612 forks, 1,920 commits, 257 releases, 338 open issues with new ones filed daily — active but young, still in public beta under Vercel beta terms (APIs may change before GA). Docs at eve.dev.

Eve vs Flue

Flue is the open-source TypeScript agent framework led by Fred Schott (Astro creator; team at Cloudflare), announced May 1, 2026, 1.0 Beta on June 16, built on Pi, the open-source minimal harness (same harness as OpenClaw). Flue 2 added React-style Agent Hooks.

The two look near-identical: both define agents declaratively, Markdown for instructions/skills, typed TS tool files (both literally name the helper defineTool), durability as table stakes, a sandbox per agent, subagents, channels-as-files, MCP support — and both independently used the "Next.js for agents" framing.

The real difference is the seams, not the structure. Durability primitive: Flue uses Durable Streams (append-only event log; recovery by replay), Eve uses checkpointed durable workflows (recovery by resume). State stores: Flue offers Postgres/MySQL/Redis/MongoDB/Supabase adapters plus a SQLite-backed Durable Object on Cloudflare; Eve uses Workflow SDK state on Vercel infrastructure. Tool schemas: valibot (Flue) vs Zod (Eve). And above all, deployment: Flue is multi-cloud (Node, Cloudflare Workers/Durable Objects, GitHub Actions, GitLab CI); Eve is Vercel-first (other platforms promised; self-host as Node is possible, with the community's vercel-labs/steve as an official self-hosted reference). Schott himself told latent.space: "Eve, I think, is the most directly competitive," with host portability as Flue's defining principle — "The best tools are the ones that float above the host."

Practical shorthand from builders: pick Flue if you need multi-cloud/edge and BYO state store; pick Eve if you're already on Vercel and want the tightest path from agent to deployed production surface.

What people are saying

Warm but thin. Fred Schott was generous on the record: "Eve, I think, is the most directly competitive. It came around at the same time, so it had that same take that a harness is built-in." Firecrawl called it "the agent framework moment": "not a coincidence or a copy... it is what happens when an idea is ready." Brian at Dawn (cacheplane) framed it as validation: "This is not a threat. This is validation... Two teams, working separately, landed on agents-as-directories."

Builders validate the DX: mager went from skeptical of the "Next.js for agents" framing to convinced after shipping; dennysentinel says the bet is "that production agents need persistence, sandboxing, and approvals by default." The lock-in critiques are concrete: bitdoze's Mastra-vs-Eve notes strong Vercel lock-in, beta APIs, and ~$0.128/hr sandbox compute (~$92/mo per always-on agent). Malte Ubl (Vercel CTO) told The Register the feature is simplicity: "fill in the blanks" — "The life cycle of the agent is completely orchestrated by the framework."

Adoption signals are early: the Vercel × Rillet case study (Oct 9) claims eve agents turn customer requests into PRs — 800+ tickets in four months from two engineers, shipping rate tripled — but at Agent Conf 2026 a live audience poll found "Who had used Eve? Almost nobody." Awareness is high, hands-on use is still early. And stated plainly: no prominent Hacker News thread on the eve launch surfaced, no canonical Reddit thread was found, and X launch posts couldn't be opened directly.
