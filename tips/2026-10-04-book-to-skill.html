book-to-skill: turn any technical book into a Claude Code skill

Added Oct 4 · original article

The breakout hit of the Agent Skills ecosystem: the tool that made every technical book you own addressable by your AI assistant.

What the project is

book-to-skill (MIT, created May 2026) is a converter and an agent skill in one. Point it at a technical book — PDF, EPUB, DOCX, HTML, Markdown, RTF, MOBI/AZW — or a whole folder, and it produces a structured "skill" your coding agent loads on demand: a SKILL.md core (~4k tokens) with named frameworks, decision rules ("Use X when Y"), anti-patterns and worked examples, plus per-chapter files (~1k tokens each, loaded on demand), a glossary, a patterns file, and a cheatsheet. The design doctrine is "structure, not a summary": the spec forbids raw passages (Quality Rule #7, partly to keep generated skills fair-use-safe), and the project ships no book content itself — extraction runs locally on your machine.

Two halves. (1) A deterministic Python extractor: Docling for technical PDFs (preserves tables/code blocks, ~1.5s/page), pdftotext → pypdf → pdfminer for prose, ebooklib for EPUBs, with stdlib fallbacks so the base install is dependency-free. (2) A spec-driven generator: your own agent follows the repo's SKILL.md to analyze the book's structure, write per-chapter summaries, and assemble the glossary/patterns/cheatsheet. The skill lands in the cross-agent ~/.agents/skills/ directory, and it works with any host implementing the open Agent Skills standard — Claude Code, GitHub Copilot CLI, Amp, OpenAI Codex, Hermes Agent, OpenCode, OpenClaw. Four modes: full conversion, analyze-only, generate-from-analysis, and update/fold-in (merge new sources into an existing skill).

How it works and repo state

Repo state (verified live 2026-10-04): 33,700 stars, 3,527 forks, 202 commits, 15 open issues (mostly extraction edge cases), 5 releases with v1.4.0 an extraction-reliability release, actively maintained (commits as recent as Sep 29). It ships a mkdocs docs site, pytest suite, evals, Security CI (CodeQL, Bandit, Zizmor), a prompt-injection scanner for generated skills, and a copyright/fair-use section.

The economics claim: 24–51× fewer tokens per query than dumping the book into context (methodology in docs/performance.md), at roughly $1 per book conversion — the argument is that a PDF-reading agent re-navigates the document every turn ("the Discovery Loop Tax"), while book-to-skill pays the structuring cost once. Intended users: developers who re-read technical books and internal docs, and teams wanting architecture decision records, runbooks, onboarding guides, or specs converted into agent-queryable form.

What people are saying

Remarkably thin for a 33k-star project. The only HN thread (posted by ethanpil, June 23, 2026) has 3 points and a single comment — "Tooop" from the repo author himself. No substantive blog posts, newsletter features, YouTube reviews, or viral X threads surfaced.

What does exist: awesome-list inclusion (awesome-claude-code, awesome-ai-engineering, scriptbyai's Claude Code resource list); a third-party benchmark scoring it 88/100, calling it "a batch workload where cost savings are directly measurable"; rapid star velocity (~6.8k/month); and a derivative ecosystem — youtube-to-skill and video-to-skill explicitly follow its conventions, Londeren ships a differently-philosophied book-to-skill plugin, and bundles embed adaptations. The author also runs a sister project, x-to-skill, converting an X account's posts into a skill. The honest gap: nobody found a launch narrative explaining why 33k stars accumulated with almost no press — likely skills-directory traffic or word-of-mouth in agent communities.

What to take away

This is the canonical example of the 2026 Agent Skills open-standard wave: a tool that turns a personal library into addressable agent memory, with measured token economics and a serious security posture (prompt-injection scanning of generated skills is unusual). For a tech lead building an AI foundation platform, the pattern matters more than the project: convert the books and docs your team re-reads into on-demand skills instead of re-dumping them into context every time. And for the SaaS: runbooks, onboarding guides, and ADRs are exactly the "re-open often enough to wish you'd memorized it" candidates the repo targets.

Caveats to carry: extraction quality varies with PDF source quality, generated-skill quality is model-tier sensitive, and the 24–51× figure is the project's own measured claim — not independently reproduced.
