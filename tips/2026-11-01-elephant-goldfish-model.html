Google's Elephant-Goldfish Model: design with an elephant, review with a goldfish

Added Nov 1 · original article

First, the name lies: EGM is not a model — no weights, no API. It is Google's open-source plugin for spec-driven development: an Elephant session with full project memory drafts the design and writes zero code, then Goldfish reviewers with zero memory of the conversation read the spec cold and try to break it. Thousands of Google engineers reportedly use it daily; the method is the most transferable agent-workflow pattern of the month.

What it is

Despite the repo name, there is no model here: google/elephant-goldfish-model (Apache 2.0, ~8.5K stars, 516 forks, open-sourced in late October 2026, and explicitly 'not an officially supported Google product') is seven skills and nine reviewer personas, all written in Markdown, installable as a plugin into Antigravity, Claude Code, and Codex. The README says thousands of Google engineers use it to ship production code. The idea comes from Dave Rensin's essay 'Elephants, Goldfish, and the New Golden Age of Software Engineering.'

The method, in the README's own slogan: 'Design with an elephant. Review with a goldfish.' The Elephant is your long-running session: it holds the whole project, the requirements, and the earlier decisions, interviews you about trade-offs, and drafts the specification — under a strict no-code rule. The Goldfish are fresh subagents spawned with zero memory of your conversation: they get only the document and its referenced source material, and their job is to expose unstated assumptions, unclear requirements, and implementation risks. You resolve the trade-offs and approve the spec before anyone implements. Use it when a feature needs design decisions first; the README itself says to skip it for a small, clear bug fix.

The workflow runs in three commands. /egm:egm-brainstorm explores the idea with fresh reviewers challenging the proposal and saves the agreed direction in concepts_brief.md. /egm:egm-draft turns the brief into design_draft.md, pausing after each section for your feedback. /egm:egm-review sends the draft to fresh reviewers across five stages: one reads the whole document and has to explain the design back — if it gets the plan wrong, the document counts as ambiguous and goes back for drafting — and a final reviewer makes a go/no-go call on whether file paths, data structures, and function signatures are all present and unambiguous. Approved specs are saved under docs/designs/. Four more skills round it out: Resolve (work through review findings), Bootstrap (document an existing codebase), Review loop (a configured reviewer group for a specific task), and Drift report (compare checked-in docs against current code).

Installation is one command per agent: 'agy plugin install' for Antigravity, 'claude plugin marketplace add google/elephant-goldfish-model' then 'install egm@egm' for Claude Code (version 2.1.271 or later, because older versions cannot keep the goldfish properly isolated), and the equivalent for Codex. Goldfish reviews require fresh subagent contexts — if your agent cannot create them, EGM stops the review rather than faking it. The README is explicit that a review does not replace tests or human judgment.

What people are saying

Coverage converges on the same core insight, phrased different ways: the failure mode of AI-assisted development is not that the agent forgets, it is that the agent remembers what you meant instead of what you wrote. Help Net Security's summary is the cleanest: the Elephant interviews you and keeps the record; each Goldfish is stateless and therefore does not carry the design conversation's blind spots. BetaNews and the Medium deep-dives repeat Google's 'thousands of Googlers use it daily' line and stress the order-of-operations flip: no code until a design exists, has been read cold, and has been approved by you.

The independent reads add the caveats the announcement skips. One Medium walkthrough that read all seven SKILL.md files and all nine persona prompts concludes it is worth the overhead for any feature with a real architectural decision, and not worth it for a one-line fix — the same line the README draws. Reposquare's guide notes the whole thing only works if you install the complete plugin, since review steps read persona files and document standards that sit beside the skills; a single SKILL.md alone is not enough. Help Net Security flags a real gap: security flaws are not on the reviewers' list by name — you would need to add a security-minded Goldfish persona yourself, which the customizable personas allow. And one number circulating in coverage — that the cold review catches '90% of unstated assumptions' — is an author's claim from a Medium post, not a measured result from Google; treat it as enthusiasm, not evidence.

What to take away

This is the third appearance in a month of the same pattern, and that is the story: Cloudflare's audit skill separated finder from verifier, ARTEMIS Pro added a read-only Checker to its Operator, and now EGM separates the drafter from the reviewer by a hard context wall. For agent-platform work, the transferable principle is that verification must be structurally independent of creation — not a second prompt in the same chat, but a fresh context that cannot lean on shared memory. If you are building agent workflows at Riot, EGM's five-stage review (especially the 'explain it back' comprehension test and the go/no-go completeness check) is a template worth stealing even if you never install the plugin.

For the SaaS, it is directly tryable this week: install it in Claude Code or Antigravity, pick one feature with a real design decision, and run brainstorm → draft → review before any code. The discipline it enforces — spec first, approved by a human, saved under docs/designs/ — is also the missing piece for the team's lagging AI transition: it makes the agent's work reviewable by humans who were not in the room. Two things to set up deliberately: a security Goldfish (since the default reviewers do not cover it) and a drift-report habit, so the approved designs do not silently rot as the code moves on.
