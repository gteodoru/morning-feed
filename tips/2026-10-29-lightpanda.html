Lightpanda: the headless browser built from scratch for machines, not humans

Added Oct 29 · original article

Lightpanda is a headless browser written from scratch in Zig — no Chromium, no rendering, no layout engine — built for machines, not humans. Version 1.0 landed October 2, 2026, and the independent tests say the vendor's 9x/16x claims shrink to ~2x on real sites — which is still a real win, with a Chromium fallback as the honest setup.

What it is

Lightpanda (lightpanda.io, repo lightpanda-io/browser, AGPL-3.0, ~37.7K stars, 1,835 forks, 11,326 commits) is a headless browser built from scratch in Zig over two years — not a Chromium fork, not a WebKit patch. It runs JavaScript with V8, parses HTML with html5ever, and skips graphical rendering entirely: no layout, no paint, no GPU, no screenshots. What it builds is the DOM and the JavaScript environment — exactly what automation, scraping, and AI agents actually consume.

Version 1.0 shipped October 2, 2026 (1.0.1 followed October 15), exiting beta after 10,000+ commits. At release the project reported 1,739,845 Web Platform Tests subtests passing — up from 2,645 in November 2024, roughly 80% of Chrome's count — plus CORS enforcement by default and V8 15.5.35.13. The team says some companies already process over 30 million pages a day with it.

It speaks the protocols your existing tooling already uses: CDP (Puppeteer, Playwright, chromedp) and WebDriver BiDi (Selenium), so scripts connect to a Lightpanda endpoint instead of launching Chrome — one line changes. It also ships a native agent mode (plain-language driving that exports a deterministic, token-free PandaScript you can replay without a model at runtime), an MCP server with per-session isolation (each agent gets its own page, cookies, and memory), and a managed cloud offer where you pick the Lightpanda or Chrome engine per workload. Integrations already include Vercel's agent-browser CLI, OpenClaw, Dust, Nous Research, and trigger.dev. The founders (Francis and Pierre, ex-scraping-at-scale) fund it with a managed cloud browser-as-a-service.

The vendor benchmark: requesting 933 real pages on an AWS EC2 m5.large, 5 seconds vs 46 for headless Chrome and 123MB peak memory vs 2GB — '9x faster, 16x lighter.' Note the benchmark page itself is a homemade demo site, with the team explaining it is used 'because Lightpanda browser is not yet fully compliant.'

What people are saying

The Show HN thread (319 points, 137 comments) from the founders' launch post set the tone: genuine excitement that someone finally rebuilt the browser for machines, tempered by 'most websites will fail or crash' honesty from the team itself in beta.

The most useful independent check is doccraft's: 28 real JavaScript homepages, Lightpanda 1.0.1 vs headless Chromium on the same day. With the default wait setting Lightpanda built only 12 of 28; with one wait flag changed it built 21 in the first run and 22 in the second — and on the sites it built, its extracted text matched Chromium closely. The measured gap was far more modest than the vendor's: about 1.8–2.4x faster and 2.8–4.5x less memory, with the memory advantage shrinking as Chromium shared one browser across pages. His conclusion is the practical one: Lightpanda-first with a completeness check, failed pages falling back to Chromium.

Decodo's proxy tutorial (updated Oct 26, 2026) adds the anti-bot picture: on protected pages with identical residential proxies, Chrome with a desktop user agent loaded 7 of 9, Lightpanda 5, default headless Chrome 3 — and HTTP clients alone loaded 6, a reminder that the browser is not always the hard part. A webfuse comparison found a concrete coverage gap: Stripe's docs SPA rendered no body text because indexedDB and Element.scrollTo were unimplemented in the tested nightly. And the AGPL-3.0 license matters if you embed rather than just run it — self-hosting over Docker is free, but the copyleft terms deserve a read before it goes inside a commercial product. Telemetry is also on by default (LIGHTPANDA_DISABLE_TELEMETRY=true turns it off).

What to take away

For the Riot platform work, this is the cost-and-scale side of the agent-infra story that has been running all month: agents that browse the web at fleet scale cannot each carry a full Chrome. Lightpanda is the most credible 'browser for machines' bet yet — 1.0, real WPT coverage, CDP-compatible so existing Playwright/Puppeteer code just connects. The honest architecture from the independent tests is Lightpanda-first with a Chromium fallback, which is exactly how you would run it behind an agent fleet anyway: cheap and fast for the 75% of pages it handles, Chrome for the rest.

For the SaaS, the near-term use is narrower — scraping, monitoring, and agent-driven QA where screenshots don't matter — but the agent mode plus PandaScript is the interesting pattern: prototype a web task in natural language, export a deterministic script, run it token-free in production. That is the same 'record once, replay cheap' idea as the agent-skills work, applied to the browser. Watch Web API coverage (the Stripe indexedDB gap is the kind of thing that bites silently) and keep the AGPL terms in mind before embedding.
