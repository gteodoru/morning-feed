Flue: the TypeScript framework for durable AI agents

Added Oct 10 · original article

Like Claude Code, but 100% headless and programmable — an early 'Next.js for agents' bet from the Astro team.

What it is

Flue (flueframework.com) is an open-source TypeScript framework for building durable, autonomous AI agents, launched May 1, 2026 by Astro co-creator Fred Schott's team. The pitch: an agent is a model pointed at a harness — sessions, tools, skills, sandbox, durable execution — and Flue supplies that harness as a programmable, headless framework: "like Claude Code, but 100% headless and programmable. No TUI. No GUI. Just TypeScript."

From the getting-started guide: agents are plain functions marked with a 'use agent' directive, composed with a React-like hooks API — useModel, useTool, useSkill, useSandbox, useSubagent, usePersistentState, useMcpConnection (16 built-ins in Flue 2.0, the "first stable release" announced July 31, 2026). It is built on the Pi harness (pi-agent-core), supports any Pi model provider, and deploys to Node.js, Cloudflare Workers, GitHub Actions/GitLab CI, Daytona, and Render. Durability comes from Durable Streams — an append-only event log where "accepted work is never lost."

The repo (github.com/withastro/flue, Apache-2.0, created Feb 7, 2026): 8,443 stars, 508 forks, 1,134 commits, 65 open issues with activity this week (Oct 1–7, 2026), 2.x line current. Docs are deep — full guides, API reference, migration guide, blog, offline CLI docs — though pages carry no visible publication dates. It's aimed at TypeScript teams that want to own their agent stack and embed agents in real systems.

What people are saying

Fred Schott's X launch thread drew big attention (reported ~291K views; like counts disagree across sources — treat engagement numbers as unverified). Matt Pocock retweeted it; Addy Osmani replied "This is super well done, Fred!"

The HN launch thread (104 points, 56 comments, May 2) was lively but skeptical: "pretty immature... why use this?" (egonschiele), "Mastra has tests and this project doesn't" (esprehn) — countered by builders like steve_adams_86 framing harnesses as "a state machine with very explicit directives," and the_mitsuhiko's key clarification that "Flue is built on top of pi." Additional HN items (47979985, 48563881, 49127458) tracked follow-ups.

Press/community: Firecrawl's "framework moment" analysis pits Flue against Vercel's Eve (launched June 2026) — both converging on the same durable, model-agnostic, deploy-anywhere design; Better Stack has a YouTube walkthrough; Flavio Copes wrote a guide; Redline published an open-source agent framework comparison; and a Python port, PyFlue, already exists. Beyond the launch, public discussion is thin: no verified Reddit threads, no mentions in TLDR/Bytes/Latent Space/The Neuron, no mainstream tech-press coverage found.

What to take away

Flue matters as an early "Next.js for agents" entrant: the bet is that agents need a real framework — durable execution primitives, model-agnostic providers, deploy-anywhere posture — rather than another chat wrapper. The design convergence with Vercel's Eve is the signal: the durable-execution primitive and the model-agnostic stance are where the ecosystem is heading.

For a tech lead building an AI foundation platform, this is directly relevant to the harness-vs-runtime question — and worth knowing that Flue sits on the Pi harness lineage (pi-agent-core), the same family as the Cloudflare PiHarness integration from the Oct 5 Morning Feed. Caveats: it's still young (2.0 is the first stable), community traction is real but narrow (8.4K stars, thin discussion beyond launch), and there's no funding angle — this is a craft story, not a venture one.
