Big model, cheap decider: what the evidence says on Opus 5.5 + Jev, Codex Sol + Jev, and OpenAI's Decisions API

Added Oct 7 · original article

One big model to think, one cheap model to decide, and plain code to enforce — the evidence says the combination beats either model alone, but only when the questions are atomic and the confidence numbers are yours.

The question

There is a lot of hype around pairing a frontier model — Claude Opus 5.5, or Codex running GPT-6 Sol — with a cheap, fast "decision model" like TypeSafe's Jev, or with OpenAI's new Luna-based Decisions API. The pattern under the hype is one architectural claim: let the big model interpret, plan, and generate; let a small model answer only small, typed, probability-backed questions (route, triage, gate); let ordinary application code enforce permissions and execute. The decision model never generates text — it picks among options you supplied. Nobody in the field has found a case where the decision model should be the only safeguard. This piece collects the practical examples and measured evidence of what the combination looks like when it is done well — and where it breaks.

What good looks like: the pattern

The strongest pattern in the wild is the division of labor spelled out in the Jev + Opus 5.5 writeups: Opus 5.5 reads the repo, plans, writes the code; Jev sits at the decision points — picking the next action from a fixed list, judging whether a shell command is safe, deciding whether a failing test needs the frontier model's attention or is probably an environment problem, scoring completion against acceptance criteria. The critical operational line, repeated across the best writeups: the decision model answers questions, application code enforces permissions. Jev approving with high probability does not mean the action is authorized — your code still validates tool name, arguments, user permissions, and resource scope. Each component does its own job, and none quietly does another's.

The other half of the pattern is confidence-gated escalation: ask the cheap model first with a threshold, fall back to the frontier model only when confidence is low. One working example (tested Sept 25, 2026): send the ticket to Jev, use its answer above a 0.9 threshold, otherwise send the same message and options to Opus 5.5 — that combination matched Opus-level accuracy at 38–45% of the cost. In code it is literally one extra if-statement. The lesson generalizes: the confidence number is the routing switch, not the answer itself.

Opus 5.5 + Jev: the evidence

The most rigorous head-to-head comes from claude-x-jev, which ran Jev 1.13 against Claude Opus 5.5 on 216 real emails with four classification questions each. Jev took 0.3 seconds per email against Opus's 1.3s; all 216 emails cost $0.01 on Jev versus $4.73 on Opus — roughly 400x cheaper. They agreed on 87–94% of labels. The number that matters: when Jev reported at least 70% confidence (82% of the inbox), it matched Claude 95.5% of the time; when less confident, only 47% — and it told you which was which. It was also deterministic where Opus drifted, and on four of the 28 disagreements Claude hallucinated deals that weren't there (a debate-club invite became "brand deal, budget stated") — Jev can't make things up because it has no words to make them up with.

Two engineering details from real repos are worth copying. jev-opus re-decides the effort level for every Claude Code step with a Jev "reflex" — and keeps the prompt cache alive by replaying every earlier inserted effort statement byte-identically on later requests, so the cached prefix stays valid (effort went medium → low → high → high → low in one prompt while cache reads grew 24.5k → 32.3k). claude-subagent-router uses an Opus 5.5 lead with a Jev classifier picking the builder (Sonnet 5.5 or Opus) per sub-task from the brief text — with a deliberate offline keyword fallback, a guard so Sonnet never runs at max effort, and the rule that the lead's pick stands when nothing answers. Fallbacks are part of the pattern, not an afterthought.

Codex Sol + Jev: the evidence

The same routing idea shows up in the Codex world, where GPT-6 Sol plays the role of the value-priced execution engine. codex-router-lite makes Jev 1.13 the sole classifier and routes each request to astra-xhigh (exceptional reasoning, security-sensitive), astra-medium (planning, review), sol-medium (implementation and concrete debugging with decisive verification), or luna-max (bounded retrieval, tiny mechanical work) — with Sol-medium as the default when the work mode is unclear or classification is uncertain. Note the security hygiene: only the genuine latest user turn enters the decision request; tool outputs, assistant answers, and reasoning never do, so a poisoned tool output can't steer the classifier.

jev-codex-factory uses Jev in three distinct roles, which is the cleanest taxonomy seen so far: (1) execution shape — SINGLE_AGENT / DECOMPOSE / NEEDS_HUMAN, and decomposition only happens when it creates genuinely independent work; (2) model routing into lanes (LUNA_LOW up through SOL_HIGH to ASTRA_HIGH, with low-confidence routing falling back to a safer lane); (3) post-failure decisions — RETRY_SAME, RETRY_HIGHER_EFFORT, ESCALATE_MODEL, BLOCKED_RESOURCE, NEEDS_HUMAN, STOP — which gives the system the useful distinction between "the model needs to think harder" and "the model literally cannot proceed." A Codex plugin (ericwanderlust/jev-codex-router) goes one step further and has Jev pick (model, effort) per call across Codex's GPT-6 Luna/Sol/Astra, including continuations after tools — treating every model call as a routing decision, not just the first one.

Sol + OpenAI's Decisions API: the evidence

OpenAI's Decisions API, announced at DevDay (Sept 29) and in public beta since Oct 5, is the closed, first-party version of the same idea, running on GPT-6 Luna — a model otherwise tuned for focused, high-volume tasks. The request shape is three parts: the model, the shared input (text or images), and a questions array. Three question types: predicate (probability 0–1 that a condition holds, e.g. visible damage in a product photo), choice (pick from fixed options with per-option probabilities plus a confidence field, e.g. routing a complaint to billing vs shipping), and score (probability-weighted average over ordered severity levels). Pricing from the beta thread: $0.10 per million input tokens, with no output-token charges at all — the narrow interface is the price point.

The practical patterns are already emerging. The Strands Agents integration shows two of them: (1) an intent router running as agent hooks, mapping intents to tools with confidence scores (book_hotel at 0.97); (2) a ModelRouter where the router's candidate models become the decision choices, and Luna picks which model serves the turn — routed on the opening attempt only, so the strong model doesn't pay the routing tax repeatedly.

Early independent tests are humbling, though. One developer compared Decisions API (Luna) against Jev on a few hundred judgment questions (Oct 6): Jev was more accurate on nuanced judgment calls, Luna made roughly 3x as many confident wrong answers; on narrow factual yes/no checks they were about equal; Jev's median turn was 0.3s against Luna's 1.6s, and Luna cost 2–3x more. The verdict: "Jev is the better default." Treat it as a strong early signal, not a benchmark — the sample is small and game-flavored. Open questions on the API: no published API reference yet, calibration of the probabilities is unverified (one HN reader guessed they're uncalibrated softmax scores), and batch/flex tiers are unconfirmed. Luna has image support and the OpenAI ecosystem behind it; verify calibration on your own labels before trusting the confidence numbers.

The craft lessons (where good actually lives)

Three craft lessons repeat across every serious test, and they are where "good" actually lives.

First, question atomization is everything. The independent jev-phishing-bench (2,000 emails) asked the single question "is this phishing?": Jev scored 62.6%, Claude Haiku 4.5 scored 81.3% — worse than a two-line regex (91.8%). Then the author asked five narrow questions and combined them with a small logistic regression fitted on labeled data: Jev hit 95.0%, Haiku 93.2% (statistically tied) — at ~27x cheaper and 5x faster than Haiku. Atomization was worth 32 points. The awesome-jev guide's 60-second decision tree encodes the hard corollary: if a regex or rule already solves it at 90%+, keep the rule.

Second, calibration is yours to earn. Samuel Sacco's difficulty ladder found Jev's probabilities overstate the low end and understate the high end — but everything at 0.9 or above was right. The consistent advice: treat the number as a score, not a truth, and fit your own cut-offs on a few hundred labeled cases. pdlug's real-user test is the cautionary counterpart: hosted p50 latency was ~850ms for Clef vs ~110ms for Jev on his workload, directly contradicting vendor microbenches — measure p50/p95 and dollars-per-1k-decisions on your own distribution.

Third, decompose before you decide, and never decide alone. From the jev-code skill's field guide: reach for the decision model when you're about to write a regex for a semantic judgment ("is this a flaky test?"), triage CI failures, screen fetched pages for prompt injection, or rank findings by severity — and skip it when a test can settle the fact, when the call is obvious with context in view, or when you need prose. And per the Medium piece's caution: the decision model judges; code authorizes.

What to take away

For a platform builder, this is the control-plane pattern for agentic AI — the same containment discipline the industry is converging on from every direction (KPMG's 93% budget-blowout survey, the Collibra/Trail ML runtime-enforcement acquisition, Anthropic's GLM-5.3 cyber post). The decision layer is where budgets get capped, permissions get gated, and escalations get a real confidence number behind them.

If you run one experiment this week, make it this: pick one decision your agent currently asks the big model to make — model routing, test-failure triage, tool-call gating. Ask it as five narrow typed questions instead of one, fit a threshold on your own labels, and let low confidence fall through to the frontier model. That single if-statement, measured on your distribution, is the cheapest credible path from hype to evidence.
