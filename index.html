The agent-sandbox wave: Microsoft MxC, Microsoft Quicksand, AWS Strands Box

X — @simonw · Oct 8

Microsoft shipped MxC (one policy API over every OS sandbox, already inside Codex) and Quicksand (rootless QEMU VMs from Python), while AWS's Strands Box enforces semantic rules like “push only if tests passed.”

Three different design points landed the same day, via @simonw's thread, and they solve different layers of the problem:

**microsoft/mxc** (MIT, Rust, ~1.9K stars) puts one policy API over every OS's sandbox — AppContainer/Windows Sandbox on Windows, bubblewrap/LXC on Linux, Seatbelt on macOS — with versioned JSON policy describing filesystem, network and UI rules. It is already pinned as a native Windows sandbox backend inside OpenAI's Codex (codex-rs/mxc-sandbox). If you need Windows isolation, this is now the most credible option, and the Codex integration is a working reference.

**microsoft/quicksand** (MIT, Python) gives you real QEMU VMs from Python with no root and no Docker: `async with Sandbox(image="ubuntu") as sb: await sb.execute(...)`. Networking is off by default; checkpoint/revert makes it a natural fit for eval harnesses that need resettable environments.

**strands-agents/box** (Strands Box, Apache-2.0) works at the level of meaning, not syscalls. Marc Brooker's blog explains why OS sandboxes aren't enough: network traffic is mostly TLS ciphertext, so you can't write rich rules at the syscall layer. Box forces a single route out of the sandbox through a user-space policy layer with temporal, conditional rules — “allow git push only if tests passed in the last 15 minutes” — and injects API credentials itself so the agent never holds them.

Read alongside the backdoor story, the rule of thumb: VM or OS sandbox for containment, plus semantic policy and credential injection so a compromised model can't exfiltrate what it never holds.

Quail: plan queries and inference together for 14x faster AI-SQL

X — @sh_reya · Oct 7

CMU's open-source Quail runs “LLM in a WHERE clause” queries up to 14x faster than stock vLLM by letting the query plan — which knows the future access pattern — drive KV-cache retention and eviction.

Shreya Shankar's team at CMU's Full Stack Data Lab built an open-source engine for “LLM in a WHERE clause” queries that treats the query plan as the inference server's brain. Classical optimizer moves (predicate ordering by cost-per-rejection, join-order search with an “anchor” document) drive KV-cache decisions: prompts put the shared document first and the question last, then “rewind” the KV to the end of the document after the TRUE/FALSE answer, keeping KV only for rows that survive.

On a 29-query benchmark (IMDB, BioDEX medical reports, fact-checking, legal, agent traces; Qwen3 4B FP8 on one H100 vs vLLM 0.26.0): 1.84x geometric-mean speedup, and on the largest join — 5,000 medical reports against 4,144 reaction terms — 29 minutes versus 6.84 hours (14x), at $1.93/query instead of $27.03. A 100k-review two-filter query cost $0.37 on Modal.

Even if you don't adopt it, copy three ideas into your own pipelines: put the shared document first and the question last, keep KV only for rows you'll revisit, and constrain the output to label tokens.

Agents rewriting infrastructure: astral-html, tsc-rs, and the maintenance question

X — @charliermarsh; @theo · Oct 7

Astral's agent-written HTML parser is ~2x faster than the incumbents; Theo's agent-written TypeScript compiler cost ~$20k of Opus tokens — and “probably won't be maintained.”

Two data points from the week on agent-written core tooling:

Astral (@charliermarsh) replaced a third-party HTML parser with one written 100% by GPT-6 Astra inside Codex: ~2x faster, one dependency (memchr), no unsafe, ~40% of the lines. Correctness comes from the html5lib tokenizer conformance suite — Charlie's argument for why parsers suit agents: they have specs, conformance suites and fuzzing, so the agent has an objective oracle to iterate against. His question: “should we just do this for everything?”

Theo (@theo) announced tsc-rs, a complete Rust rewrite of the TypeScript compiler, type checker and LSP that agents worked on for five months: “I burned ~$400k of Codex tokens and got nowhere. Burned ~$20k of Opus and got there in 2 weeks.” Then the honest part: when asked whether it will be maintained, Theo answered “Probably not.”

The lesson to carry: look in your dependency tree for components with a public spec and a conformance suite — parsers, serializers, codecs — those are the low-risk places to let an agent write a smaller, faster replacement. Don't start a rewrite you can't maintain.

OSC 7501: a terminal standard for "what is my agent doing"

X — @mitchellh · Oct 8

Mitchell Hashimoto's OSC 7501 is a dozen-line escape-sequence standard for “what is my agent doing” — replacing the heuristic arms race of regex-matching spinner characters in window titles. Claude Code already adopted it.

Mitchell Hashimoto (of Ghostty) published OSC 7501, a tiny escape-sequence standard — `ESC ] 7501 ; state=working:... ST` — that lets any long-running terminal program, especially coding agents, report its status: idle, working, done, blocked, error, plus optional progress, “blocked on permission/question/auth” kinds, and base64 messages. Terminals that don't understand it ignore it; when the process exits, stale records are dropped.

Why it exists: “agent inbox” tools currently guess agent status with fragile heuristics like regex-matching spinner characters in window titles (one tool's Claude Code rules changed ten times in three months) or side-channel sockets that break over SSH and in containers. Claude Code is the first production adopter; libghostty-vt parses it; proof-of-concept patches for Terraform, Codex and Homebrew took “no more than a dozen lines” each.

If you ship a CLI agent or long-running tool, emit it. It's about a dozen lines, or a shell one-liner.

ChatGPT's "Intelligent UI", reverse-engineered

X — @rabi_guha; TechCrunch · Oct 8

ChatGPT now answers with generated diagrams, buttons and working tools instead of text — and a reverse-engineer found the trick: the agent emits a constrained intermediate language, never raw code.

Rabi Shanker Guha reverse-engineered the mechanism: the agent never writes raw code. If you build generative UI: the reported pattern is a constrained intermediate language compiled server-side onto a fixed component library, not raw model-written HTML. That buys safety, streaming and a consistent look.

Chollet: exponential progress on super-exponential capex means diminishing returns

X — @fchollet · Oct 8

Chollet: AI progress fits an exponential, but AI capex is growing super-exponentially — so each extra dollar buys less progress, and the financing story matters as much as the research story.

François Chollet's (@fchollet) argument, from the AI Technical list: most measures of AI progress closely fit an exponential over 2023–2026, while AI capex over the same period has been slightly super-exponential — the rate of growth itself is increasing, i.e. the doubling time is shrinking. If progress grows like a fixed exponential while investment grows faster than any fixed exponential, then each doubling of progress needs more than a doubling of investment. Output per unit of input keeps shrinking.

It frames the capex debate — AWS's $220B plan for 2026, the FT revenue story, the Firmus IPO — as a returns question: if the investment curve has to keep bending upward just to hold progress on its exponential, the financing story matters as much as the research story. Chollet's answer to the skeptics: benchmark error rates halve over fixed intervals (exponential), and the training/inference split has stayed roughly 60/40, so capex being “just inference demand” doesn't change the fit.
